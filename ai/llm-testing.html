01Пирамида тестов

У LLM-фич три проблемы: ответы недетерминированы, каждый вызов стоит денег, а прогон идёт секундами. Поэтому основание пирамиды — тесты без модели, а настоящая модель — только наверху:

  • Обычный код — юнит-тесты: валидация запроса, нормализация телефона, каждый инструмент как PHP-класс.
  • Контракт агента — настоящий агент и инструменты против поддельной модели со скриптованными ответами.
  • Повтор записанных ответов (кассеты) — реальный ответ провайдера, проигранный без сети.
  • Живые диалоги — настоящая модель, включаются вручную.
  • Оценки качества (evals) — набор сценариев и проверок при смене модели или промпта.

02Инструменты — обычные классы

Инструмент — это функция с входом и выходом, его тестируют без всякой модели. Особенно важны отказы:

public function testRefusesWhenPhoneDoesNotMatchOrder(): void
{
    $tool = $this->toolWithOrder(number: 1001, phone: '79000000001');

    $result = ($tool)(orderNumber: '1001', phone: '+7 900 000-00-99');

    self::assertStringContainsString('Телефон не совпадает', $result);
    self::assertStringNotContainsString('Статус', $result);   // статус не утёк
}

public function testExtractsNumberFromFreeText(): void
{
    $tool = $this->toolWithOrder(number: 1001, phone: '79000000001');

    self::assertStringContainsString('Заказ №1001', ($tool)('заказ №1001', '89000000001'));
}

03Контракт агента с поддельной моделью

Цепочка «модель просит инструмент → библиотека вызывает PHP-класс → результат уходит обратно модели» проверяется с моделью, которая отвечает по сценарию. Так дёшево и одинаково при каждом прогоне.

public function testToolRefusalReachesFinalAnswerUnchanged(): void
{
    $model = new ScriptedModel([
        ToolCall::of('get_order_by_number', ['orderNumber' => '1001', 'phone' => '79000000099']),
        fn (array $toolResults) => 'Не могу показать детали: ' . $toolResults[0],   // финальный ответ
    ]);
    $agent = $this->agentWith($model, tools: [$this->orderTool]);

    $answer = $agent->call('Где мой заказ 1001? Мой телефон 79000000099');

    self::assertStringContainsString('Телефон не совпадает', $answer);
}

ScriptedModel здесь — тестовая подмена платформы: очередь заранее заданных ответов вместо HTTP-запросов.

04Записанные ответы (кассеты)

  • Один раз прогоняем сценарий против настоящего API и записываем HTTP-ответы в файл.
  • В обычных прогонах подменяем HTTP-клиент: ответы берутся из файла — без сети и без оплаты.
  • Перед коммитом вычищаем ключи из записанного файла.
  • Если кассеты ещё нет, тест помечается пропущенным, а не падает.

Кассеты ловят регрессии в разборе ответа провайдера — например, когда библиотека или формат ответа обновились.

05Живые диалоги

Многоходовые разговоры с настоящей моделью и настоящими инструментами показывают, как ассистент ведёт себя целиком. Но они тратят токены и могут создать реальные записи — поэтому выключены по умолчанию:

AI_LIVE_TESTS=1 OPENROUTER_API_KEY=... php bin/phpunit tests/Integration/Ai/AssistantLiveDialogueTest.php --testdox
  • Ключ передаётся явно, а в конфигурации тестов по умолчанию пустой — случайный прогон ничего не потратит.
  • Транскрипт печатается по ходу теста — удобно читать глазами.
  • Запускайте на тестовой базе: инструменты могут создать заявку.

06Оценки качества (evals)

Перед сменой модели или правкой промпта прогоните набор типичных диалогов и проверьте не точный текст, а свойства ответа:

  • вызван нужный инструмент с нужными аргументами;
  • в ответе нет цен, которых не вернул инструмент;
  • ассистент не назвал статус чужого заказа;
  • ответ на русском и короче N символов.

Запомнить

  • Больше всего тестов — без модели.
  • Отказы инструментов тестируются первыми.
  • Живые тесты — только по явному флагу.
  • Проверяйте свойства ответа, а не точный текст.

Частые ошибки

  • Каждый прогон CI ходит в платный API.
  • Ключ в записанной кассете.
  • assertEquals на текст ответа модели.
  • Смена модели без прогона сценариев.
