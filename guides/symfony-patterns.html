01 · Dependency InjectionВнедрение зависимостей — фундамент всего Symfony

Задача

Сервис оформления заказа сам создаёт репозиторий, почтовый клиент и логгер через new. Его невозможно протестировать и сложно перенастроить.

Решение

Сервис только объявляет, что ему нужно, в конструкторе. Создаёт и передаёт зависимости контейнер Symfony — по типам аргументов (autowiring).

namespace App\Order;

use App\Repository\OrderRepository;
use Psr\Log\LoggerInterface;
use Symfony\Component\DependencyInjection\Attribute\Autowire;
use Symfony\Component\Mailer\MailerInterface;

final class CheckoutService
{
    public function __construct(
        private readonly OrderRepository $orders,
        private readonly MailerInterface $mailer,
        private readonly LoggerInterface $logger,
        // скалярные значения тоже внедряются — например, из .env
        #[Autowire(env: 'SHOP_EMAIL')]
        private readonly string $shopEmail,
    ) {}

    public function checkout(Cart $cart): Order
    {
        $order = Order::fromCart($cart);
        $this->orders->save($order);
        $this->logger->info('Order created', ['id' => $order->getId()]);

        return $order;
    }
}

Когда применять

  • Всегда: в Symfony это способ по умолчанию.
  • Зависите от интерфейсов (MailerInterface), а не от конкретных классов.

Подводные камни

  • Не берите сервисы из контейнера вручную ($container->get()) — это Service Locator, он прячет зависимости.
  • Больше 5–6 зависимостей в конструкторе — сигнал, что класс делает слишком много.

02 · RepositoryКоллекция сущностей, которая прячет детали хранения

Задача

DQL-запросы для поиска запчастей разбросаны по контроллерам. Один и тот же запрос «в наличии и подходит к модели» написан в трёх местах по-разному.

Решение

Все запросы к сущности собираются в одном классе с понятными методами: findAvailableForModel(). Остальной код не знает про SQL и Doctrine.

namespace App\Repository;

use App\Entity\Part;
use Doctrine\Bundle\DoctrineBundle\Repository\ServiceEntityRepository;
use Doctrine\Persistence\ManagerRegistry;

/** @extends ServiceEntityRepository<Part> */
class PartRepository extends ServiceEntityRepository
{
    public function __construct(ManagerRegistry $registry)
    {
        parent::__construct($registry, Part::class);
    }

    /** @return Part[] */
    public function findAvailableForModel(string $carModel): array
    {
        return $this->createQueryBuilder('p')
            ->andWhere('p.carModel = :model')
            ->andWhere('p.stock > 0')
            ->setParameter('model', $carModel)
            ->orderBy('p.price', 'ASC')
            ->getQuery()
            ->getResult();
    }

    public function save(Part $part): void
    {
        $this->getEntityManager()->persist($part);
        $this->getEntityManager()->flush();
    }
}

Когда применять

  • Любой запрос сложнее find($id) — в метод репозитория с говорящим именем.
  • Если нужно подменять хранилище в тестах, выделите интерфейс PartRepositoryInterface.

Подводные камни

  • Не кладите в репозиторий бизнес-логику — только чтение и запись.
  • flush() в каждом save() удобен, но в пакетных операциях лучше вызывать его один раз в конце.

03 · FactoryСоздание объекта по правилам в одном месте

Задача

Сумма заказа хранится то в рублях, то в копейках, то строкой. Где-то забыли умножить на 100 — и клиенту выставили счёт в 100 раз меньше.

Решение

Закрытый конструктор и именованные фабричные методы: объект можно создать только корректным способом, а название метода объясняет, что передаётся.

namespace App\Money;

final class Money
{
    private function __construct(private readonly int $kopecks)
    {
        if ($kopecks < 0) {
            throw new \InvalidArgumentException('Сумма не может быть отрицательной');
        }
    }

    public static function fromRubles(float $rubles): self
    {
        return new self((int) round($rubles * 100));
    }

    public static function fromKopecks(int $kopecks): self
    {
        return new self($kopecks);
    }

    public function add(self $other): self
    {
        return new self($this->kopecks + $other->kopecks);
    }
}

// Использование — невозможно перепутать единицы
$total = Money::fromRubles(1499.90)->add(Money::fromKopecks(30000));

Для сервисов, которые сложно собрать (например, клиент платёжной системы с настройками из окружения), Symfony умеет вызывать фабрику сам:

services:
    App\Payment\PaymentClient:
        factory: ['@App\Payment\PaymentClientFactory', 'create']

Когда применять

  • Объект можно создать несколькими способами.
  • При создании нужно проверить данные или выбрать реализацию.

Подводные камни

  • Не делайте фабрику ради фабрики: если хватает new с понятными аргументами — используйте new.

04 · BuilderПошаговая сборка сложного объекта

Задача

Каталог фильтруется по марке, цене, наличию и бренду, и любой фильтр может быть не задан. Склеивать строку запроса через if — путь к ошибкам и SQL-инъекциям.

Решение

Собирать запрос по шагам: каждый метод добавляет одно условие и возвращает сам объект. Так устроены Doctrine QueryBuilder и FormBuilder в Symfony.

public function search(PartFilter $filter): array
{
    $qb = $this->createQueryBuilder('p');

    if ($filter->brand !== null) {
        $qb->andWhere('p.brand = :brand')->setParameter('brand', $filter->brand);
    }
    if ($filter->maxPrice !== null) {
        $qb->andWhere('p.price <= :max')->setParameter('max', $filter->maxPrice);
    }
    if ($filter->onlyInStock) {
        $qb->andWhere('p.stock > 0');
    }

    return $qb->orderBy('p.price', 'ASC')
        ->setMaxResults(50)
        ->getQuery()
        ->getResult();
}

Когда применять

  • У объекта много необязательных параметров.
  • Удобно для тестовых данных: OrderBuilder::new()->paid()->withItems(3)->build().

Подводные камни

  • Параметры передавайте через setParameter(), а не склейкой строк: иначе SQL-инъекция.

05 · DecoratorНовое поведение без изменения исходного класса

Задача

Сервис курсов валют ходит во внешний API на каждый запрос. API медленный и с лимитами. Добавлять кеш прямо в сервис — смешивать две ответственности.

Решение

Обернуть сервис в декоратор с тем же интерфейсом. Декоратор отдаёт значение из кеша, а при промахе зовёт оригинал. Symfony подставит декоратор везде вместо оригинала.

namespace App\Currency;

use Symfony\Component\DependencyInjection\Attribute\AsDecorator;
use Symfony\Component\DependencyInjection\Attribute\AutowireDecorated;
use Symfony\Contracts\Cache\CacheInterface;
use Symfony\Contracts\Cache\ItemInterface;

#[AsDecorator(decorates: HttpExchangeRates::class)]
final class CachedExchangeRates implements ExchangeRatesInterface
{
    public function __construct(
        #[AutowireDecorated] private readonly ExchangeRatesInterface $inner,
        private readonly CacheInterface $cache,
    ) {}

    public function rate(string $currency): float
    {
        return $this->cache->get('rate_' . $currency, function (ItemInterface $item) use ($currency) {
            $item->expiresAfter(3600); // час
            return $this->inner->rate($currency);
        });
    }
}

Когда применять

  • Кеш, логирование, повторные попытки, метрики вокруг существующего сервиса.
  • Когда исходный класс чужой или его нельзя менять.

Подводные камни

  • Декоратор обязан реализовать весь интерфейс, даже методы, которые просто проксирует.
  • Цепочка из трёх-четырёх декораторов усложняет отладку — следите за порядком (priority).

06 · AdapterПриводит чужой интерфейс к вашему

Задача

SMS отправляет старый SDK провайдера с неудобным методом sendMessage($sender, $phone, $text). Через полгода провайдера сменят, а вызовы SDK уже по всему коду.

Решение

Код зависит от своего интерфейса SmsSenderInterface. Адаптер реализует его и внутри переводит вызов на язык SDK. Смена провайдера — это новый адаптер, остальной код не трогаем.

namespace App\Notification;

interface SmsSenderInterface
{
    public function send(string $phone, string $text): void;
}

final class LegacySmsAdapter implements SmsSenderInterface
{
    public function __construct(
        private readonly \Vendor\Sms\OldSmsClient $client, // чужой SDK
        private readonly string $senderName = 'ZAPCHASTI',
    ) {}

    public function send(string $phone, string $text): void
    {
        $result = $this->client->sendMessage($this->senderName, ltrim($phone, '+'), $text);

        if ($result['status'] !== 'OK') {
            throw new SmsNotSentException($result['error'] ?? 'unknown');
        }
    }
}

Когда применять

  • Интеграции: платёжки, SMS, службы доставки, внешние API.
  • Когда хочется изолировать код от библиотеки, которую могут заменить.

Подводные камни

  • Адаптер переводит интерфейс, а не добавляет логику. Если появилась логика — это уже сервис.
  • Переводите и ошибки: исключения SDK превращайте в свои.

07 · StrategyВзаимозаменяемые алгоритмы за общим интерфейсом

Задача

Стоимость доставки считается по-разному: курьер, самовывоз, транспортная компания. Метод с switch на 200 строк растёт с каждым новым способом.

Решение

Каждый способ — отдельный класс-стратегия. Symfony сам находит все стратегии по тегу и складывает их в локатор, а калькулятор выбирает нужную по ключу.

namespace App\Delivery;

use Symfony\Component\DependencyInjection\Attribute\AsTaggedItem;
use Symfony\Component\DependencyInjection\Attribute\AutoconfigureTag;

#[AutoconfigureTag('app.delivery')] // все реализации получат этот тег автоматически
interface DeliveryStrategy
{
    public function cost(Order $order): Money;
}

#[AsTaggedItem(index: 'courier')]
final class CourierDelivery implements DeliveryStrategy
{
    public function cost(Order $order): Money
    {
        return Money::fromRubles(300 + 25 * $order->distanceKm());
    }
}

#[AsTaggedItem(index: 'pickup')]
final class PickupDelivery implements DeliveryStrategy
{
    public function cost(Order $order): Money
    {
        return Money::fromRubles(0);
    }
}
namespace App\Delivery;

use Psr\Container\ContainerInterface;
use Symfony\Component\DependencyInjection\Attribute\AutowireLocator;

final class DeliveryCalculator
{
    public function __construct(
        #[AutowireLocator('app.delivery')] private readonly ContainerInterface $strategies,
    ) {}

    public function cost(Order $order, string $method): Money
    {
        if (!$this->strategies->has($method)) {
            throw new UnknownDeliveryMethod($method);
        }

        return $this->strategies->get($method)->cost($order);
    }
}

Новый способ доставки — это один новый класс с #[AsTaggedItem]. Калькулятор менять не нужно.

Когда применять

  • Доставка, оплата, скидки, экспорт в разные форматы.
  • Когда в коде растёт switch по типу.

Подводные камни

  • Локатор создаёт стратегии лениво — только при get(). Если нужны все сразу, используйте #[AutowireIterator].
  • Для двух вариантов, которые никогда не расширятся, обычный if проще.
Поведенческий

08 · ObserverEventDispatcher: «что-то случилось» — и все заинтересованные узнают

Задача

После оплаты заказа нужно отправить письмо, списать остатки, начислить бонусы и уведомить склад. Метод оплаты знает обо всех этих сервисах и превращается в свалку.

Решение

Оплата только сообщает о событии OrderPaid. Каждый слушатель подписывается сам и делает свою часть. Новая реакция — новый слушатель, без правки оплаты.

namespace App\Order\Event;

use Symfony\Contracts\EventDispatcher\Event;

final class OrderPaid extends Event
{
    public function __construct(public readonly Order $order) {}
}

// В сервисе оплаты
$this->dispatcher->dispatch(new OrderPaid($order));
namespace App\Stock;

use App\Order\Event\OrderPaid;
use Symfony\Component\EventDispatcher\Attribute\AsEventListener;

final class ReserveStockOnOrderPaid
{
    public function __construct(private readonly StockService $stock) {}

    #[AsEventListener(event: OrderPaid::class)]
    public function onOrderPaid(OrderPaid $event): void
    {
        foreach ($event->order->items() as $item) {
            $this->stock->reserve($item->partId(), $item->quantity());
        }
    }
}

Когда применять

  • Побочные действия, которые не влияют на результат основной операции.
  • Расширение чужого кода: события ядра Symfony (kernel.request, kernel.exception).

Подводные камни

  • Слушатели выполняются синхронно: медленное письмо задержит ответ пользователю. Тяжёлое — в Messenger (следующий паттерн).
  • Неочевидный порядок: при зависимостях задавайте priority.
Поведенческий

09 · CommandMessenger: действие как объект, который можно выполнить позже

Задача

Генерация PDF-счёта и отправка письма занимают 3–5 секунд. Пользователь ждёт, а при сбое почтового сервера заказ падает с ошибкой.

Решение

Упаковать действие в объект-команду с данными и отдать в шину. Обработчик выполнит его — сразу или в фоне через очередь, с повторами при сбоях.

namespace App\Invoice;

// Команда — только данные. Передавайте id, а не сущность: её не сериализовать в очередь
final readonly class SendInvoice
{
    public function __construct(public int $orderId) {}
}
namespace App\Invoice;

use Symfony\Component\Messenger\Attribute\AsMessageHandler;

#[AsMessageHandler]
final class SendInvoiceHandler
{
    public function __construct(
        private readonly OrderRepository $orders,
        private readonly InvoiceMailer $mailer,
    ) {}

    public function __invoke(SendInvoice $command): void
    {
        $order = $this->orders->find($command->orderId);
        $this->mailer->send($order);
    }
}

// В контроллере: ответ уходит сразу, письмо — в фоне
$bus->dispatch(new SendInvoice($order->getId()));
framework:
    messenger:
        transports:
            async: '%env(MESSENGER_TRANSPORT_DSN)%'   # например, redis:// или doctrine://default
        routing:
            App\Invoice\SendInvoice: async

Когда применять

  • Долгие и ненадёжные операции: письма, PDF, вызовы внешних API.
  • Когда одно действие запускают из разных мест: контроллер, консоль, крон.

Подводные камни

  • Нужен запущенный воркер: php bin/console messenger:consume async.
  • Обработчик может выполниться повторно — делайте его идемпотентным.

10 · Chain of ResponsibilityЦепочка обработчиков, каждый решает — обработать или передать дальше

Задача

Для каждой команды в шине нужно писать в лог время выполнения, а ошибки отправлять в мониторинг. Добавлять это в каждый обработчик — копипаста.

Решение

Middleware Messenger — это цепочка: каждое звено делает свою часть и передаёт сообщение следующему через $stack->next(). Так же устроены HTTP-middleware и Voters в Security.

namespace App\Messenger;

use Psr\Log\LoggerInterface;
use Symfony\Component\Messenger\Envelope;
use Symfony\Component\Messenger\Middleware\MiddlewareInterface;
use Symfony\Component\Messenger\Middleware\StackInterface;

final class TimingMiddleware implements MiddlewareInterface
{
    public function __construct(private readonly LoggerInterface $logger) {}

    public function handle(Envelope $envelope, StackInterface $stack): Envelope
    {
        $start = microtime(true);

        try {
            return $stack->next()->handle($envelope, $stack); // передаём дальше по цепочке
        } finally {
            $this->logger->info('Message handled', [
                'message' => $envelope->getMessage()::class,
                'ms' => round((microtime(true) - $start) * 1000),
            ]);
        }
    }
}
framework:
    messenger:
        buses:
            messenger.bus.default:
                middleware:
                    - App\Messenger\TimingMiddleware

Когда применять

  • Сквозная логика вокруг множества операций: логи, транзакции, проверка прав.
  • Последовательные проверки, где любая может остановить процесс.

Подводные камни

  • Забыли вызвать $stack->next() — сообщение молча не обработается.
  • Порядок звеньев важен: middleware выполняются в порядке объявления.

Бонус: почему в Symfony не пишут Singleton

Классический Singleton со статическим getInstance() — глобальное состояние: его не подменить в тестах, и зависимости класса скрыты. В Symfony это не нужно: сервисы в контейнере по умолчанию и так создаются один раз на запрос и переиспользуются везде, где их внедрили.

// Не нужно
final class Config
{
    private static ?self $instance = null;
    public static function getInstance(): self { return self::$instance ??= new self(); }
}

// Достаточно обычного сервиса — контейнер сам создаст его один раз
final class Config
{
    public function __construct(#[Autowire('%kernel.project_dir%')] private readonly string $root) {}
}
