01Пакеты

Symfony AI — набор компонентов для работы с моделями: платформы (провайдеры), агент с инструментами, чат с хранением истории и бандл для конфигурации.

composer require symfony/ai-bundle symfony/ai-agent symfony/ai-chat symfony/ai-open-router-platform

Компоненты пока в версиях 0.x, и API между ними меняется. Фиксируйте версии в composer.json и читайте журнал изменений перед обновлением.

02Агент и чат в конфигурации

ai:
    platform:
        openrouter:
            api_key: '%env(OPENROUTER_API_KEY)%'
            http_client: openrouter.client       # клиент с таймаутом и повторами

    agent:
        assistant:
            platform: 'ai.platform.openrouter'
            model: 'anthropic/claude-haiku-5.5'
            prompt: |
                Ты — помощник магазина автозапчастей. Отвечай коротко, по-русски, на «вы».
                Цену, наличие и адрес бери только из инструментов.
            tools: true                          # все сервисы с #[AsTool]
            max_tool_calls: 8                    # защита от зацикливания

    chat:
        assistant:
            agent: 'ai.agent.assistant'
            message_store: 'App\Ai\ChatMessageStore'   # своя история в базе

03Инструменты на атрибутах

Любой сервис с #[AsTool] попадает в набор инструментов агента. Параметры __invoke() превращаются в JSON-схему, а описание — в подсказку модели.

#[AsTool(
    name: 'find_parts',
    description: 'Цена и наличие запчасти по артикулу в выбранном пункте выдачи. Карточки клиент видит отдельно — не придумывай другие цены.',
)]
final class FindPartsTool
{
    public function __invoke(string $article, ?string $brand = null): string { /* … */ }
}

04Контекст запроса

Инструментам нужно знать, кто в чате, но модель не должна передавать это аргументом. Решение — сервис-контекст: контроллер заполняет его перед вызовом модели, инструменты читают.

final class ChatContext
{
    private ?ChatProfile $profile = null;

    public function set(ChatProfile $profile): void { $this->profile = $profile; }
    public function profile(): ?ChatProfile { return $this->profile; }
}

// в инструменте: телефон из аргумента, если клиент назвал его в чате, иначе — из профиля
$phone = PhoneNormalizer::normalize($phone ?? $this->context->profile()?->getPhone());

Профиль чата хранится в базе: телефон с сайта, выбранный пункт выдачи, имя, город, VIN — всё, что ассистент узнал за разговор. Чтобы модель не переспрашивала, процессор входа агента (InputProcessorInterface) перед каждым вызовом добавляет эти данные в начало истории.

05История диалога

Компонент чата сам добавляет новое сообщение к истории и отправляет её агенту. Историю храним в своей таблице через MessageStoreInterface:

use Symfony\AI\Chat\ChatInterface;
use Symfony\AI\Platform\Message\Message;

$this->context->set($profile);                       // кто в чате — для инструментов
$answer = $this->chat->submit(Message::ofUser($request->message));

return [
    'reply' => trim((string) $answer->asText()),
    'products' => $this->offers->all(),              // карточки, которые положил find_parts
    'options' => $this->replyOptions->all(),         // кнопки быстрых ответов
];

06Карточки и кнопки рядом с текстом

Инструменты кладут структурированные данные в «мешки» (сервисы, живущие один запрос), а контроллер отдаёт их фронтенду рядом с текстом ответа:

  • Карточки товаров — цена и наличие из базы, а не пересказ модели.
  • Быстрые ответы — кнопки «Да, этот пункт», «Другой город» под сообщением.
  • Модель в тексте только комментирует: «Есть два варианта, оба в вашем пункте выдачи».

07Эксплуатация

  • Если ключ не задан, эндпоинт отвечает 503 «Ассистент не настроен», а не падает.
  • Ошибки провайдера → 502 с понятным текстом; ключ в логах маскируется.
  • Модель меняется одной строкой конфига — держите запасные варианты закомментированными с пометками о скорости и цене.

Запомнить

  • Фиксируйте версии пакетов 0.x.
  • Инструменты — сервисы с #[AsTool].
  • Личность клиента — из контекста запроса.
  • Карточки и кнопки — отдельно от текста.

Частые ошибки

  • Обновление symfony/ai-* без чтения изменений.
  • Телефон клиента как обязательный аргумент модели.
  • История диалога только в памяти процесса.
  • Цены в тексте ответа модели.
