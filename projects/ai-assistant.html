01Задача

Магазину автозапчастей нужен ассистент на сайте, который снимет с менеджеров типовые вопросы: есть ли деталь и сколько стоит, где ближайший пункт выдачи и до скольки он работает, где мой заказ. Сложное — передать человеку, не теряя то, что клиент уже рассказал.

  • Никаких выдуманных цен. Модель не знает остатков и прайса — всё берётся из базы через инструменты.
  • Чужие данные недоступны. Статус заказа — только тому, чей это заказ, даже если запрос отправлен в обход сайта.
  • Быстро. Клиент в чате не ждёт минуту: ответ вместе с поиском — за секунды.
  • Модель можно сменить одной строкой конфигурации, не переписывая код.

    04Инструменты

    Каждый инструмент — сервис с атрибутом #[AsTool]. Описание объясняет модели, когда его вызывать, а проверки живут в коде.

    get_order_by_numberСтатус заказа — только если телефон собеседника совпадает с телефоном в заказе.
    save_qualificationЗапоминает в профиле чата имя, город, пункт выдачи, VIN и что ищет клиент.
    search_helpОтветы из справки магазина: гарантия, возврат, выбор пункта.

    #[AsTool(
    name: 'get_order_by_number',
    description: 'Статус одного заказа по номеру. Телефон подтверждает, что заказ принадлежит клиенту. '
        .'Если телефон уже известен из профиля, параметр phone не нужен.',
)]
final class GetOrderByNumberTool
{
    public function __invoke(string $orderNumber, ?string $phone = null): string
    {
        $phone = PhoneNormalizer::normalize($phone ?? $this->context->profile()?->getPhone());
        if ($phone === null) {
            return 'Телефон не известен. Попроси клиента назвать телефон из заказа.';
        }

        $order = $this->orders->findByNumber($orderNumber);
        if ($order === null) {
            return 'Заказ с таким номером не найден.';
        }

        if (!in_array($phone, $order->phones(), true)) {
            return 'Телефон не совпадает с заказом. Детали заказа не сообщай.';
        }

        return sprintf('Заказ №%s: %s, пункт выдачи: %s', $order->number(), $order->statusLabel(), $order->branchAddress());
    }
}

    05Контекст клиента

    Если клиент вошёл на сайт, ассистент не должен спрашивать его телефон. Поэтому сайт передаёт контекст, а бэкенд хранит профиль чата:

    • Профиль в базе: телефон и id с сайта, имя, город, выбранный пункт выдачи, VIN и что ищет клиент. Переживает перезагрузку страницы.
    • Контекст запроса — сервис, который контроллер заполняет до вызова модели. Инструменты берут телефон оттуда, поэтому он для модели необязательный аргумент.
    • Процессор входа агента перед каждым вызовом добавляет известные данные профиля в начало истории — модель не переспрашивает город и машину.
    • Быстрые ответы и карточки инструменты кладут в отдельные списки, которые уходят на фронтенд рядом с текстом: кнопки «Да, этот пункт», карточки с ценой из базы.

    06Защита от подмены контекста

    Контекст приходит в теле запроса, а тело может прислать кто угодно — через curl или консоль браузера, с чужим телефоном. Поэтому контроллер доверяет контексту, только если запрос подписан секретом, который знает лишь сервер сайта:

    $payload = $request->toArray();

if (!$this->isTrustedSite($request)) {
    // Без секрета context — просто поле из запроса, а не личность клиента
    unset($payload['context']);
}

private function isTrustedSite(Request $request): bool
{
    $provided = (string) $request->headers->get('X-Ai-Site-Secret', '');

    // hash_equals сравнивает за постоянное время: секрет не подобрать по задержке ответа
    return $this->siteSecret !== '' && $provided !== '' && hash_equals($this->siteSecret, $provided);
}
    • Права — в коде инструментов, а не в промпте. Уговорить модель можно, обойти if в PHP — нет. Отказ инструмент возвращает текстом, и модель передаёт его клиенту.
    • Ключ API не попадает в логи: перед записью ошибки он заменяется на [redacted].
    • Лимит вызовов инструментов за ход защищает от зацикливания и лишних расходов.
    • Модель не перепечатывает цены: карточки идут из базы отдельно от её текста.

    Подробнее о рисках LLM-приложений — в гайде «Безопасность LLM-приложений».

    07Модель, скорость и надёжность

    • Быстрая модель без рассуждения. Исходная модель «думала» перед ответом, и клиент ждал 20–46 секунд. Быстрая модель отвечает за ~16 секунд вместе с вызовами инструментов — для подбора запчастей точности хватает.
    • Смена модели — одна строка. OpenRouter даёт единый API к разным провайдерам; в конфиге закомментированы запасные варианты с пометками о скорости и цене.
    • Таймаут 60 секунд и два повтора на ответы 429 и 5xx — через отдельный HTTP-клиент Symfony только для OpenRouter.
    • Общий нормализатор телефонов вместо копий в каждом инструменте: «8 900…», «+7 (900)…» и «900…» приводятся к одному виду.

    08Как это проверено

    LLM отвечает по-разному, стоит денег и работает секундами, поэтому большинство тестов обходится без настоящей модели:

    УровеньЧто проверяет
    Юнит-тестыРазбор запроса чата (пустое сообщение, подмена id сессии, кривой контекст), нормализация телефонов и инструмент заказа — 8 сценариев, включая «телефон не совпал — детали не утекли».
    Контракт агентаНастоящий агент Symfony AI с инструментом, но модель — скриптованная подмена. Проверяет цепочку «модель → инструмент → модель» и что отказ по безопасности доходит до ответа без изменений.
    КассетыЗаписанные ответы OpenRouter проигрываются без сети. Пока кассета не записана, тест помечается пропущенным, а не падает.
    Живые диалогиМногоходовые разговоры с настоящей моделью и инструментами. Запускаются только явно: AI_LIVE_TESTS=1 и ключ в окружении.

    Подход подробно — в гайде «Тестирование LLM-функций».
