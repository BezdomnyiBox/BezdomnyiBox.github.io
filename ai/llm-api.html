01Модель — это функция от текста

Языковая модель получает список сообщений и возвращает следующее сообщение. Она ничего не помнит между запросами: историю диалога каждый раз отправляет ваше приложение.

POST https://openrouter.ai/api/v1/chat/completions
Authorization: Bearer <ключ из переменной окружения>
Content-Type: application/json

{
  "model": "anthropic/claude-haiku-5.5",
  "messages": [
    { "role": "system", "content": "Ты помощник магазина автозапчастей. Отвечай коротко, на «вы»." },
    { "role": "user", "content": "Есть масляный фильтр на Solaris?" }
  ],
  "max_tokens": 300,
  "temperature": 0.3
}
{
  "choices": [{
    "message": { "role": "assistant", "content": "Подскажите, пожалуйста, год выпуска и объём двигателя." },
    "finish_reason": "stop"
  }],
  "usage": { "prompt_tokens": 48, "completion_tokens": 21 }
}

OpenRouter — это шлюз: один ключ и один формат запроса для моделей разных компаний. Сменить модель — значит поменять одну строку model.

02Роли сообщений

  • system — правила поведения: кто ассистент, как отвечать, чего не делать. Читается моделью в начале каждого запроса.
  • user — сообщения клиента.
  • assistant — прошлые ответы модели. Их нужно отправлять обратно, иначе модель «забудет» разговор.
  • tool — результаты вызова ваших инструментов (подробно — в гайде про tool calling).

Системный промпт — это не секрет и не защита. Пользователь может уговорить модель пересказать его, поэтому ключи, пароли и внутренние правила доступа туда не кладут.

03Токены и окно контекста

  • Модель читает и пишет токенами — кусками слов. Русский текст обычно занимает больше токенов, чем такой же английский.
  • Окно контекста — сколько токенов модель видит за раз: системный промпт, вся история, описания инструментов и ответ.
  • Каждый новый ход отправляет всю историю заново, поэтому длинный диалог дорожает с каждым сообщением.
  • Стоимость = входные токены × цена входа + выходные токены × цена выхода. Выход обычно в несколько раз дороже входа.

Длинную историю обрезают или сжимают: оставляют последние N сообщений, а старые заменяют кратким пересказом.

04Параметры генерации

  • temperature — степень случайности. 0–0,3 для фактов и работы с инструментами, выше — для творческих текстов.
  • max_tokens — потолок длины ответа. Защищает от бесконечного текста и неожиданных счетов.
  • Модели с рассуждением (reasoning) сначала «думают» скрытым текстом — отвечают точнее в сложных задачах, но дольше и дороже.

Из практики: в чате поддержки замена модели с рассуждением на быструю модель без него сократила время ответа с 20–46 до ~16 секунд вместе с вызовами инструментов — качества для подбора запчастей хватило.

05Как выбрать модель

  • Скорость важнее ума в чатах с клиентами: каждые лишние 10 секунд ожидания теряют собеседника.
  • Надёжный вызов инструментов — главное требование для ассистента, который ищет данные. Проверяйте на своих сценариях, а не по рейтингам.
  • Цена считается на реальных диалогах: средняя длина истории × число сообщений в день.
  • Держите 2–3 запасные модели в конфиге закомментированными — переключение займёт минуту.

06Надёжность: таймауты и повторы

Модели отвечают секундами, а провайдеры иногда отдают 429 (слишком много запросов) или 5xx. Запрос должен иметь таймаут и повторы с паузой:

framework:
    http_client:
        scoped_clients:
            openrouter.client:
                base_uri: 'https://openrouter.ai/'
                timeout: 60
                retry_failed:
                    http_codes:
                        429: true
                        502: true
                        503: true
                        504: true
                    max_retries: 2

Повторять можно только запрос к модели. Если инструмент уже создал заявку или заказ, повтор всего хода создаст дубль — такие действия должны быть идемпотентными.

07Ответ пользователю

  • Стриминг — показывать ответ по мере генерации. Ощущается в разы быстрее, даже если полное время то же.
  • Структурированные данные отдельно от текста: карточки товаров, кнопки быстрых ответов. Модель не должна перепечатывать цены — она может ошибиться в цифре.
  • Понятные ошибки: «Не удалось получить ответ, попробуйте ещё раз» вместо зависшего индикатора.

Запомнить

  • Модель не помнит прошлое — историю хранит приложение.
  • Системный промпт не секрет.
  • Низкая temperature для фактов и инструментов.
  • Таймауты, повторы и потолок токенов.

Частые ошибки

  • Ключ API во фронтенде или в промпте.
  • Бесконечная история без обрезки.
  • Повтор хода, который уже создал заказ.
  • Выбор модели по рейтингу, а не на своих сценариях.
