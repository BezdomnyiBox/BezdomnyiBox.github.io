01Зачем инструменты

Модель не знает ваших цен, остатков и заказов — и не должна их придумывать. Инструмент (tool) — это функция вашего бэкенда, которую модель может попросить вызвать. Решает, когда звать, модель; выполняет — ваш код.

  • поиск товара по артикулу, пункты выдачи, график работы;
  • статус заказа, профиль клиента, прошлые обращения;
  • действия: сохранить данные клиента, передать заявку менеджеру.

02Цикл вызова

1Приложение отправляет модели историю и описания инструментов
2Модель отвечает не текстом, а просьбой: «вызови get_order_by_number с номером 1001»
3Ваш код выполняет функцию — с проверками прав — и получает результат
4Результат отправляется модели сообщением с ролью tool
↻Модель может позвать ещё инструмент — шаги 2–4 повторяются (ограничьте число повторов)
5Модель пишет финальный ответ клиенту на основе результатов
"tools": [{
  "type": "function",
  "function": {
    "name": "get_order_by_number",
    "description": "Статус заказа по номеру. Телефон обязателен: без совпадения статус не сообщается.",
    "parameters": {
      "type": "object",
      "properties": {
        "orderNumber": { "type": "string", "description": "Номер заказа из сообщения клиента" },
        "phone": { "type": "string" }
      },
      "required": ["orderNumber"]
    }
  }
}]
{
  "role": "assistant",

    "id": "call_1",
    "type": "function",
    "function": { "name": "get_order_by_number", "arguments": "{\"orderNumber\": \"1001\"}" }
  }]
}

03Описание — это промпт

Модель выбирает инструмент только по названию и описанию. Хорошее описание отвечает на три вопроса: что делает, когда вызывать, чего не делать.

❌ "Ищет заказ."

✅ "Проверяет статус одного заказа по номеру и телефону. Используй, когда клиент
   называет номер заказа, а не просит всю историю. Без совпадения телефона статус
   не сообщай. Если телефон уже известен из профиля, параметр phone не нужен."
  • Называйте инструменты глаголом и объектом: find_parts, create_manager_lead.
  • Дублируйте ключевые правила в системном промпте: «цену и наличие бери только из инструментов».
  • Меньше инструментов — меньше ошибок выбора. Десяток узких лучше одного «универсального».

04Что возвращать

  • Короткий текст с фактами, а не весь объект из базы: модели нужно 4 строки, а не 40 полей.
  • Ошибки — тоже текстом, который подсказывает следующий шаг: «Телефон не совпадает с заказом — попроси клиента назвать телефон из заказа». Исключение оборвёт весь диалог.
  • Данные для интерфейса — отдельно. Карточки товаров инструмент кладёт в отдельный список, который уходит на фронтенд рядом с текстом. Модель не перепечатывает цены и не может в них ошибиться.

05Инструменты с побочными эффектами

Чтение безопасно, а запись — нет: модель может позвать инструмент дважды или не вовремя.

  • Пишущие инструменты (заявка менеджеру, сохранение данных) — только после явного согласия клиента. Это правило — и в описании, и в промпте.
  • Делайте их идемпотентными: повторный вызов с теми же данными не создаёт дубль.
  • Ограничьте число вызовов за ход (max_tool_calls): защита от зацикливания и лишних расходов.
  • Права — в коде инструмента, а не в промпте (подробно — в гайде про безопасность).

06Инструмент на Symfony AI

В Symfony AI инструмент — обычный сервис с атрибутом #[AsTool]. Схему параметров библиотека строит из сигнатуры __invoke():

use Symfony\AI\Agent\Toolbox\Attribute\AsTool;

#[AsTool(
    name: 'get_branch_schedule',
    description: 'Часы работы и телефон пункта выдачи по его id. Вызывай, когда клиент спрашивает, когда пункт открыт.',
)]
final class GetBranchScheduleTool
{
    public function __construct(private readonly BranchRepository $branches) {}

    public function __invoke(int $branchId): string
    {
        $branch = $this->branches->find($branchId);
        if ($branch === null) {
            return 'Пункт выдачи не найден. Уточни у клиента адрес.';
        }

        return "Пункт: {$branch->getAddress()}\nЧасы работы: {$branch->getSchedule()}\nТелефон: {$branch->getPhone()}";
    }
}

07Когда агент не нужен

Агент — это модель, которая сама решает, какие инструменты звать и в каком порядке. Это гибко, но непредсказуемо и дороже.

  • Если шаги всегда одинаковые (классифицировать письмо → извлечь поля → сохранить) — пишите обычный код, а модель зовите на отдельных шагах.
  • Агент оправдан, когда путь зависит от разговора: клиент может спросить про заказ, а потом про запчасть и график.

Запомнить

  • Модель просит — ваш код выполняет и проверяет права.
  • Описание инструмента: что, когда и чего не делать.
  • Результат — короткий текст, ошибки — тоже текст.
  • Лимит вызовов и идемпотентные пишущие инструменты.

Частые ошибки

  • Один «универсальный» инструмент на всё.
  • Возврат огромных JSON-объектов модели.
  • Цены и наличие, которые модель «вспомнила» сама.
  • Проверка прав в промпте вместо кода.

Что дальше

Инструменты дают модели доступ к данным — значит, пора разобраться, как её не обмануть.
